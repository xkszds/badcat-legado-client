## 五、已确认与未确认

- 已确认：APK 内存在搜索、详情、目录、阅读、阅读设置、书架、换源、净化设置等命名布局资源。
- 已确认：同名布局存在 `layout/` 与 `layout-v17/` 等资源限定目录的情况，实际选择取决于 Android 资源匹配规则。
- 未确认：布局内部控件 ID、视图层级、点击监听、页面跳转和运行时动态布局。
- 未确认：原版净化规则的完整执行顺序、远端规则格式及所有规则数据；布局名不能替代 DEX 代码分析。
- 未完成：Legado 源码依赖接入、适配代码、Gradle 工程、编译、签名和真机安装测试。

## 六、下一步建议（按可验证顺序）

1. 使用兼容的 APK 资源解码器对目标布局做只读解码，先提取 `activity_base_read`、`activity_search_result`、`activity_book_detail`、`activity_chapter_lsit`、`activity_ad_block`。
2. 建立独立 Android 工程骨架，先固定 applicationId、minSdk、签名策略和 GPL 源码发布策略；不要覆盖原 APK。
3. 定义统一书籍/章节/进度 DTO，再编写 Legado 搜索、详情、目录、正文的 adapter 接口。
4. 把原版净化拆成正文替换、WebView 注入、视频/章节页规则三条管线，分别测试。
5. 在具备 Android SDK 与 Gradle 8.14.4、JDK 21 的构建环境后再执行编译和安装验证。
