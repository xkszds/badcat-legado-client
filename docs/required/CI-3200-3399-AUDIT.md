## 3. 每个 CI 的强制记录模板

以下字段对每个 CI 编号、每次 attempt 单独建立，不得用范围级摘要替代：

### CI #NNNN / attempt N

- **身份与快照：** workflow / event / Run ID / branch / full exact HEAD SHA / created time / conclusion。
- **Job/Step 实际执行：** 逐 Job、逐关键 Step 记录名称、状态、是否执行、日志/报告位置；标出 skipped/cancelled/pending。
- **本次具体跑通的功能：** 按成功步骤列出实际验证的模块、API、行为或产品功能；写测试类型、断言/报告证据和覆盖边界。仅凭步骤名称不推断功能。
- **失败与未覆盖项：** 每个失败/跳过/未执行步骤、直接错误、日志证据、根因类别（代码/测试/构建配置/依赖/基础设施/外部站点网络/未知）及下游未验证内容。
- **书源实际链路：** 源名称/类型、真实请求、环境/时间；搜索/发现/分页/详情/目录/正文/多页/登录/Cookie 到哪一步；明确区分 Android Runtime E2E、脱敏回放和外部 Python/HTTP 冒烟。
- **分层结论：** workflow conclusion；Job/Step；测试；功能；真实源；产品验收。不得把 CI 绿灯等同完整 Legado 兼容。
- **证据与复核：** Job ID、关键日志/报告/JUnit/产物 ID/路径/哈希、审计日期、复核结果。回写后重新读取条目核对。
