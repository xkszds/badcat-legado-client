## 1. 本册审计原则

1. 下表中的提交标题只用于历史发现和主题定位，**不能当作实际功能覆盖证据**。
2. 每一条均保留独立 CI 编号、Run ID、Attempt、完整 exact HEAD SHA、历史分支、event、状态、结论和触发时间。
3. 下列历史记录目前仅完成 Actions 元数据登记；不能把 workflow failure 推断为具体功能失败，也不能把提交标题推断为功能已跑通。
4. 每条 CI 的以下项目均须继续独立取证并回填：
   - Job/Step 名称、状态、实际执行/跳过情况、Job ID；
   - 每个成功 Step 实际跑通的模块/API/行为，以及断言、日志或报告证据；
   - 失败/跳过/取消步骤、直接错误、根因分类和未验证下游范围；
   - JUnit、测试报告、日志、artifact ID/路径/哈希；
   - 真实书源名称/类型、请求链路和到达阶段；区分 Android Runtime E2E、脱敏回放、外部 Python/HTTP；
   - workflow、Job/Step、自动化测试、功能覆盖、真实书源、产品验收六层结论；
   - 审计日期、复核人/复核状态，以及回写后重新读取复核。
5. 未取到证据一律标记“待核验/证据不可得”，不得按提交标题、workflow 名称或绿灯猜测。
6. attempt 必须按 GitHub 实际数据单独登记；本轮元数据发现的记录均为 attempt 1。若发现 rerun，必须新增独立 attempt 记录，不覆盖 attempt 1。
