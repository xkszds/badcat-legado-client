## 2. Scanner self-test coverage and gaps

The existing scanner self-test covers:
- Kotlin/Java source-root identity and cross-module import cycles.
- Explicit and wildcard imports, Kotlin aliases, top-level functions.
- Kotlin extension functions/properties and nested generic signatures.
- Java static and static-wildcard imports.
- Generated Android symbol and dependency-provided symbol classifications.
- Deterministic JSON generation and missing-seed detection.

However, its own declared limitations confirm:
- Same-package references without imports are not graph edges.
- Fully-qualified usages in declarations and string-evaluated scripts can be missed.
- Reflection, generated Kotlin/Java, KSP/KAPT, service-loader metadata and JNI are unresolved.
- Gradle variants, source-set exclusions, manifest/resource linking and dependency substitution are not evaluated.
- Wildcard imports are conservative and do not include nested packages automatically.
- It does not prove Kotlin overload/type resolution.

Therefore, the existing scanner is useful but does not yet meet the registered G2 acceptance criteria. The scanner self-test passing (when confirmed by the active workflow) cannot be represented as complete source-closure proof.
